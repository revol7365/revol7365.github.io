STL은 컨테이너와 알고리즘 외에도 **특정 목적을 위한 유틸리티 클래스**를 제공한다.
이번 강에서는 "값이 있을 수도 없을 수도 있는" `optional`, "무슨 타입이든 담는" `any`, "정해진 타입 중 하나만 담는" `variant`,
시간을 다루는 `chrono`, 그리고 메모리를 자동으로 관리하는 스마트 포인터와 난수 라이브러리를 다룬다.

## std::optional로 선택적 값 관리하기

C++17에 도입됐다.
함수가 **값을 돌려줄 수도, 못 돌려줄 수도** 있을 때 쓴다.

예를 들어 어떤 수의 소인수를 찾는 함수는 "찾았다/못 찾았다"와 "찾은 값"이라는 두 가지 정보를 돌려줘야 한다.
예전에는 `bool`을 반환하고 결과는 참조 인자로 넘기거나, `-1` 같은 특별한 값을 약속해서 썼다.
`optional`은 이 둘을 **하나의 반환값**으로 합쳐준다.

```cpp
optional<long> factor(long n) {
    for (long i : {2, 3, 5, 7, 11, 13, 17, 19}) {
        if (n % i == 0) return { i };   // 값이 있음
    }
    return {};                          // 값이 없음
}
```

### How to do it

```cpp
optional<int> a{ 42 };
cout << *a << '\n';
```

`*` 연산자로 담긴 값을 꺼낸다. 포인터처럼 생겼지만 포인터는 아니고, **값 자체를 optional 안에 품고 있다**(힙 할당 없음).

```cpp
using oint = std::optional<int>;

oint a{ 42 };
oint b{ 73 };   // 이게 oint b{} 면 값이 없는 상태(NAN 출력)가 된다

auto sum{ a + b };

if (sum) {
    cout << format("{} + {} = {}\n", *a, *b, *sum);
} else {
    cout << "NAN\n";
}
```

> **주의: `optional`끼리는 그냥 `+`가 안 된다.**
> `std::optional`은 비교 연산자는 제공하지만 **산술 연산자는 제공하지 않는다.** 위 코드가 동작하려면 연산자를 직접 오버로딩해야 한다.
>
> ```cpp
> oint operator+(const oint& a, const oint& b) {
>     if (!a || !b) return {};        // 둘 중 하나라도 비었으면 결과도 비어 있음
>     return oint{ *a + *b };
> }
>
> oint operator+(const oint& a, int b) {
>     if (!a) return {};
>     return oint{ *a + b };
> }
> ```
>
> 핵심은 **"비어 있음"이 계산 결과로 전파된다**는 점이다. 그래서 `b`가 `oint b{}`면 `sum`도 비게 되고 `NAN`이 출력된다.

### How it works

`optional` 클래스는 다양한 오버로딩을 제공한다.

```cpp
optional<int> n{ 42 };

if (n)                  // bool 변환 — 값을 가짐
if (n.has_value())      // 위와 동일, 의미가 더 명확함

x = *n;                 // 검사 없이 꺼냄 (비어 있으면 미정의 동작)
x = n.value();          // 비어 있으면 예외를 던짐
x = n.value_or(0);      // 비어 있으면 기본값 0을 반환

n.reset();              // 값을 버리고 빈 상태로
```

`*n`과 `n.value()`의 차이가 중요하다.
`*n`은 검사를 하지 않으므로 빠르지만, 비어 있는 optional에 쓰면 **미정의 동작**이다.
`value()`는 검사를 하고 비어 있으면 예외를 던진다.

### There's more

```cpp
b.reset();
try {
    cout << b.value() << '\n';
} catch (const std::bad_optional_access& e) {
    cout << format("b.value(): {}\n", e.what());
}
```

`optional` 클래스는 `value()` 메서드를 통해 예외 처리를 지원한다.
빈 optional에서 값을 꺼내려 하면 `std::bad_optional_access` 예외가 발생한다.

## 타입 안전성을 위해 std::any 사용하기

C++17에 도입됐다.
단일 객체를 **임의의 타입으로 안전하게** 저장할 수 있는 타입 안전 컨테이너를 제공한다.

```cpp
any x{};
x = 42;

if (x.has_value()) {
    cout << format("x has type: {}\n", x.type().name());
    cout << format("x has value: {}\n", any_cast<int>(x));
} else {
    cout << "no value\n";
}

// x has type: i
// x has value: 42
```

> `type().name()`이 돌려주는 문자열은 **구현체마다 다르다.** GCC/Clang에서는 맹글링된 이름이라 `int`가 `i`로 나온다.
> 사람이 읽을 이름이 필요하면 디맹글링(`abi::__cxa_demangle`)이 따로 필요하다.

`any` 클래스의 주요한 유용성은 **다형적인 함수를 생성**하는 데 있다.

### How to do it

```cpp
void p_any(const any& a) {
    if (!a.has_value()) {
        cout << "None.\n";
    } else if (a.type() == typeid(int)) {
        cout << format("int: {}\n", any_cast<int>(a));
    } else if (a.type() == typeid(string)) {
        cout << format("string: \"{}\"\n", any_cast<const string&>(a));
    } else if (a.type() == typeid(list<int>)) {
        cout << "list<int>: ";
        for (auto& i : any_cast<const list<int>&>(a)) cout << format("{} ", i);
        cout << '\n';
    } else {
        cout << format("something else: {}\n", a.type().name());
    }
}
```

최소한의 코드로 다양한 타입을 처리할 수 있다.

`any_cast<int>(a)`처럼 **값으로** 캐스팅하면 복사본이 생기고,
`any_cast<const list<int>&>(a)`처럼 **참조로** 캐스팅하면 복사 없이 원본을 본다. 컨테이너를 꺼낼 때는 참조가 유리하다.

타입이 맞지 않으면 `std::bad_any_cast` 예외가 발생한다. 그래서 "타입 안전"하다.

### How it works

`std::any`의 복사 생성자와 할당 연산자는 직접 초기화를 사용하여 대상 객체의 const가 아닌 복사본을 포함된 객체로 만든다.
포함된 객체의 타입은 `typeid` 객체로 별도로 저장된다.

즉 `any`는 **값 + 타입 정보**를 함께 들고 다닌다. 이 타입 정보 덕분에 `type()` 비교와 캐스팅 검사가 가능하다.

## std::variant로 서로 다른 타입 저장하기

C++17에 도입됐다.
한 번에 하나의 값만 가질 수 있으며, 각 값은 **동일하게 할당된 메모리 공간**에 저장된다.

`any`와 비교하면 이렇다.

| | 저장 가능한 타입 | 크기 | 힙 할당 |
| --- | --- | --- | --- |
| `any` | 무엇이든 | 구현마다 다름(작은 타입은 내부 저장) | 큰 타입은 힙 사용 가능 |
| `variant` | **선언 시 지정한 타입들 중 하나** | 가장 큰 타입 기준으로 고정 | 없음 |

### 원시적인 union 구조체와의 차이점

`variant` 클래스는 **태그된 union(tagged union)** 이다.

원시 `union`은 같은 32비트 메모리 공간에 대해 여러 가지 다른 관점을 제공한다.
즉 `uint32_t`로 저장한 값을 `float`로 꺼내 읽어도 컴파일러가 막지 않는다. 비트를 그대로 재해석할 뿐이고, 이건 대부분 **미정의 동작**이다.

```cpp
union U { uint32_t i; float f; };
U u;
u.i = 42;
cout << u.f;   // 막히지 않지만 미정의 동작 — 42의 비트를 float로 읽음
```

`variant`는 각 데이터에 **그 타입이 무엇인지 태그가 함께 붙는다.**
그래서 `uint32_t`로 저장했다면 `uint32_t`로만 꺼낼 수 있고, 다른 타입으로 꺼내려 하면 컴파일러가 막는 게 아니라 **실행 중에 `std::bad_variant_access` 예외로 잡아준다.**

```cpp
std::variant<uint32_t, float> v;
v = uint32_t{ 42 };

cout << std::get<uint32_t>(v);   // OK
cout << std::get<float>(v);      // 예외: bad_variant_access
cout << v.index();               // 0 — 현재 몇 번째 타입이 들어있는지
```

> **"타입이 하나로 고정되는 거면 그냥 그 타입 쓰면 되는 거 아닌가?"**
> 담긴 타입은 **런타임에 바뀔 수 있다.** `v = 3.14f;`를 하면 그 순간부터 `float`로만 접근할 수 있게 태그가 바뀐다.
> 즉 "여러 타입 중 하나가 들어올 수 있는데, 지금 들어있는 게 뭔지는 항상 정확히 안다"가 variant의 핵심이다. 원시 union에는 이 "지금 뭐가 들어있는지"가 없어서 프로그래머가 직접 관리해야 했다.

### How to do it

```cpp
class Animal {
    string_view _name{};
    string_view _sound{};
    Animal();
public:
    Animal(string_view n, string_view s) : _name{ n }, _sound{ s } {}
    void speak() const {
        cout << format("{} says {}\n", _name, _sound);
    }
    void sound(string_view s) {
        _sound = s;
    }
};

class Cat : public Animal {
public:
    Cat(string_view n) : Animal(n, "meow") {}
};

class Dog : public Animal {
public:
    Dog(string_view n) : Animal(n, "arf!") {}
};

class Wookie : public Animal {
public:
    Wookie(string_view n) : Animal(n, "grrraarrgghh!") {}
};

using v_animal = std::variant<Cat, Dog, Wookie>;
```

`visit()`에 넘길 **방문자(visitor)** 는 담길 수 있는 모든 타입에 대한 `operator()`를 가져야 한다.

```cpp
struct animal_speaks {
    void operator()(const Dog& d) const { d.speak(); }
    void operator()(const Cat& c) const { c.speak(); }
    void operator()(const Wookie& w) const { w.speak(); }
};

list<v_animal> pets{ Cat{"Hobbes"}, Dog{"Fido"}, Cat{"Max"}, Wookie{"Chewie"} };

cout << "visit:\n";
for (const v_animal& a : pets) {
    visit(animal_speaks{}, a);
}
cout << "\n";
```

여기서 눈여겨볼 점은 `Animal`에 **가상 함수가 하나도 없다**는 것이다.
그런데도 각 동물이 자기 소리를 낸다. 상속 기반 다형성이 아니라 **variant의 타입 태그로 분기**하는 것이기 때문이다.

### How it works

`std::variant` 클래스는 단일 객체를 위한 컨테이너다.
이 컨테이너에 대한 타입을 가져오고, 호출하고 할 수 있다.

`visit()`은 현재 variant 객체를 단일 인자로 사용하여 호출 가능한 객체를 실행한다.
내부적으로는 "지금 index가 0이면 첫 번째 오버로드, 1이면 두 번째…"를 컴파일러가 만들어주는 것이라, `if/else` 체인을 직접 쓰지 않아도 되고 **타입을 빠뜨리면 컴파일 에러가 난다.**

## std::chrono로 시간 이벤트 다루기

C++11에 도입됐고 C++20에서 크게 개선됐다.

### How to do it

`system_clock` 클래스는 현재 시간과 날짜를 얻을 수 있다.

```cpp
using std::chrono::system_clock;

auto now = system_clock::now();
cout << format("{:%Y-%m-%d %H:%M:%S}\n", now);   // C++20 chrono 서식화
```

시간 **측정** 목적으로는 `steady_clock`을 제공한다.
이는 일관된 단조(monotonic) 틱 수를 제공하도록 설계되었다.

```cpp
using std::chrono::steady_clock;
using std::chrono::duration;

auto t1 = steady_clock::now();
do_something();
auto t2 = steady_clock::now();

duration<double> secs = t2 - t1;
cout << format("{:.5}초 걸림\n", secs.count());
```

> **왜 측정에는 `system_clock`이 아니라 `steady_clock`인가?**
> `system_clock`은 벽시계라서 NTP 동기화나 사용자의 시간 변경으로 **뒤로 갈 수도 있다.** 그러면 경과 시간이 음수가 나온다.
> `steady_clock`은 절대 뒤로 가지 않는다. 대신 "몇 년 몇 월"을 알려주지는 못한다.
> 날짜/시간을 보여줄 땐 `system_clock`, 성능을 잴 땐 `steady_clock`이다.

### How it works

chrono 라이브러리는 크게 **clock 클래스**와 **duration 클래스**로 이루어져 있다.

- `clock` — 시간의 기준점(epoch)과 틱을 제공한다. `system_clock`, `steady_clock`, `high_resolution_clock`이 있다.
- `time_point` — 특정 시각. 클럭의 epoch로부터 얼마나 지났는지를 담는다.
- `duration` — 두 `time_point` 객체의 간격이다.

```cpp
using namespace std::chrono;

auto d = 3s + 500ms;                       // 리터럴로 duration 생성
auto ms = duration_cast<milliseconds>(d);  // 단위 변환
cout << ms.count() << "ms\n";              // 3500ms
```

`duration`은 **단위가 타입에 박혀 있어서** `seconds`와 `milliseconds`를 헷갈려 더하는 실수를 컴파일러가 잡아준다.
정밀도가 손실되는 변환(초 → 밀리초는 안전, 밀리초 → 초는 손실)은 `duration_cast`로 명시해야 한다.

## 가변 튜플을 위한 폴드 표현식 사용하기

`std::tuple`은 본질적으로 더 복잡하고 덜 편리한 struct다.
장점은 **폴드 표현식과 함께 사용할 수 있다**는 점이다.

가변 파라미터 팩의 확장을 쉽게 만들도록 설계된 폴드 표현식은 C++17의 신기능이다.

폴드 표현식이 없던 시절에는 재귀로 파라미터 팩을 풀어야 했다.

```cpp
// 재귀 방식 — 종료 조건용 오버로드가 따로 필요하다
template<typename T>
void f(T final) {
    cout << final << '\n';
}

template<typename T, typename... Args>
void f(T first, Args... args) {
    cout << first;
    f(args...);
}
```

폴드 표현식을 쓰면 함수 하나로 끝난다.

```cpp
template<typename... Args>
void f(Args... args) {
    (cout << ... << args);
    cout << '\n';
}
```

`(cout << ... << args)`는 **이항 왼쪽 폴드**로, `((cout << arg1) << arg2) << arg3 ...`으로 펼쳐진다.
폴드는 네 가지 형태가 있다.

| 형태 | 문법 | 펼쳐지는 모양 |
| --- | --- | --- |
| 단항 왼쪽 | `(... op pack)` | `((p1 op p2) op p3)` |
| 단항 오른쪽 | `(pack op ...)` | `(p1 op (p2 op p3))` |
| 이항 왼쪽 | `(init op ... op pack)` | `((init op p1) op p2)` |
| 이항 오른쪽 | `(pack op ... op init)` | `(p1 op (p2 op init))` |

### How to do it

```cpp
template<typename... T>
constexpr void print_t(const tuple<T...>& tup) {
    auto lpt =
        [&tup] <size_t... I> (std::index_sequence<I...>) constexpr {
            (..., ( cout <<
                format((I? ", {}" : "{}"), get<I>(tup))
            ));
            cout << '\n';
        };
    lpt(std::make_index_sequence<sizeof...(T)>());
}
```

`index_sequence` 객체를 사용하여 **인덱스 값의 파라미터 팩**을 생성한다.

동작을 뜯어보면 이렇다.

1. `sizeof...(T)`로 튜플 원소 개수를 구한다.
2. `make_index_sequence<3>()`은 `index_sequence<0, 1, 2>` 객체를 만든다.
3. 람다가 그걸 받으면서 `size_t... I`가 `0, 1, 2`로 추론된다.
4. `(..., (expr))`는 **쉼표 연산자 폴드**라서 `expr`을 I마다 한 번씩, 순서대로 실행한다.
5. `I ? ", {}" : "{}"`로 첫 원소 앞에만 쉼표를 빼준다.

> `[&tup]<size_t... I>(...)`처럼 람다에 **명시적 템플릿 파라미터 목록**을 쓰는 건 C++20 기능이다.
> `std::format`의 첫 인자는 컴파일 타임 상수여야 하는데, `I`가 템플릿 파라미터라서 `I ? ... : ...`도 상수식이 되어 통과한다.

### How it works

tuple의 단점은 제한적인 인터페이스다.
`std::tie`의 구조적 바인딩이나 `std::get<>`을 사용하여 요소를 가져올 수 있지만, **요소 개수와 타입을 모를 경우**에는 유용하지 않다.

```cpp
auto [a, b, c] = tup;     // 개수를 알아야만 쓸 수 있다
cout << get<0>(tup);      // 인덱스를 손으로 적어야 한다
```

폴드 표현식 + `index_sequence` 조합이 이 문제를 해결한다.
"몇 개인지 모르는 튜플"을 컴파일 타임에 펼쳐서 전부 순회할 수 있다.

### There's more

크기를 알 수 없는 tuple의 모든 int 값의 합을 반환하는 함수다.

```cpp
template<typename... T>
constexpr int sum_t(const tuple<T...>& tup) {
    int accum{};
    auto lpt =
        [&tup, &accum] <size_t... I> (std::index_sequence<I...>) constexpr {
            (..., (
                accum += get<I>(tup)
            ));
        };
    lpt(std::make_index_sequence<sizeof...(T)>());
    return accum;
}
```

구조는 `print_t`와 완전히 같다. `cout <<` 자리에 `accum +=`가 들어갔을 뿐이다.
**"튜플 전체를 순회하는 틀"** 을 한 번 익혀두면 하는 일만 바꿔 끼우면 된다.

## std::unique_ptr로 할당된 메모리 관리하기

`std::unique_ptr`은 **C++11**에 도입됐고, `std::make_unique` 함수가 **C++14**에서 추가됐다.

**자원 획득이 초기화(RAII)** 라는 관용구를 준수한다.
객체를 위해 메모리가 할당되면 해당 객체의 생성자가 호출되고, 객체의 소멸자가 호출될 때 메모리가 자동으로 힙에 반환된다.

### How to do it

`unique_ptr`를 단순히 생성만 하면 메모리 할당이나 관리 객체를 생성하지 않는다.

```cpp
unique_ptr<Thing> p1;               // 아무것도 할당하지 않음 (nullptr)
```

`new` 연산자를 사용하면 메모리를 할당하고 `Thing` 객체를 생성한다.

```cpp
unique_ptr<Thing> p2{ new Thing };  // 할당 + 생성
auto p3{ make_unique<Thing>() };    // 동일한 결과
```

`make_unique` 함수를 사용하여 동일한 결과를 얻을 수 있다. 이쪽이 권장되는데,
할당과 생성자 호출이 한 번에 묶여서 **예외가 끼어들 틈이 없기** 때문이다.

`unique_ptr`은 **복사 생성자가 없다.**

```cpp
auto p4 = p3;              // 컴파일 에러 — 복사 불가
auto p5 = std::move(p3);   // OK — 소유권 이전, 이제 p3는 nullptr
```

이름 그대로 "유일한" 소유자만 존재한다는 게 이 클래스의 계약이다.

### How it works

스마트 포인터는 복사 생성자와 복사 할당 연산자가 없다.
하지만 **이동은 가능하다.**

포인터를 리셋할 수도 있다.

```cpp
p2.reset();                // 관리 객체를 파괴하고 비운다
p2.reset(new Thing);       // 기존 객체를 파괴하고 새 객체를 관리
Thing* raw = p2.get();     // 소유권은 유지한 채 원시 포인터만 확인
Thing* out = p2.release(); // 소유권을 포기 — 이제 직접 delete 해야 한다
```

`unique_ptr`은 크기가 원시 포인터와 같고 런타임 오버헤드도 거의 없다.
**"기본으로 쓸 스마트 포인터"** 는 `unique_ptr`이고, 공유가 정말 필요할 때만 `shared_ptr`로 간다.

## std::shared_ptr로 객체 공유하기

`std::shared_ptr` 클래스는 관리 객체를 소유하고, **복사본을 추적하기 위해 사용 카운터를 유지**하는 스마트 포인터다.

### How to do it

`new` 연산자 또는 `make_shared()` 함수를 통해 생성된다.

```cpp
shared_ptr<Thing> p1{ new Thing };
auto p2{ make_shared<Thing>() };   // 권장
```

관리 객체는 포인터가 범위를 벗어나면 파괴되고 메모리는 힙에 반환된다.

복사를 하면 사용 카운트는 증가하지만 **새로운 객체가 생성되는 것은 아니다.**

```cpp
auto a{ make_shared<Thing>() };
cout << a.use_count() << '\n';   // 1
{
    auto b{ a };                 // 복사 — 같은 객체를 가리킴
    cout << a.use_count() << '\n';   // 2
}                                // b가 범위를 벗어남
cout << a.use_count() << '\n';   // 1
```

> `make_shared` 쪽이 권장되는 이유는 `make_unique`와 같은 예외 안전성에 더해,
> **객체와 제어 블록을 한 번의 할당으로 처리**하기 때문이다. `new`로 만들면 할당이 두 번 일어난다.

### How it works

`shared_ptr`의 복사 생성자와 복사 할당 연산자는 사용 카운터를 증가시킨다.
사용 카운트가 0이 되면 관리 객체를 파괴시키고 메모리를 힙에 반환한다.

## 공유된 객체를 위한 약한 포인터 사용하기

옵저버인 `weak_ptr`은 **그 자체로 포인터를 갖지 않는다.**

### How to do it

`shared_ptr`을 `weak_ptr`에 넣어야 한다.

```cpp
auto sp{ make_shared<Thing>() };
weak_ptr<Thing> wp{ sp };

cout << sp.use_count() << '\n';   // 1 — weak_ptr은 카운트를 올리지 않는다

if (auto locked = wp.lock()) {    // 살아 있으면 shared_ptr을 얻는다
    locked->do_something();
} else {
    cout << "이미 파괴됨\n";
}

cout << wp.expired() << '\n';     // 관리 객체가 파괴됐는지 확인
```

`weak_ptr`은 직접 역참조할 수 없다. 반드시 `lock()`으로 `shared_ptr`을 얻어서 써야 한다.
"확인하는 순간엔 살아 있었는데 쓰는 순간엔 죽어 있는" 상황을 막기 위해서다.

### How it works

`weak_ptr`은 `shared_ptr`에 대해 **소유권이 없는 참조**만 가지는 옵저버다.
사용 카운트에 영향을 주지 않으므로, `weak_ptr`이 아무리 많아도 관리 객체의 수명을 늘리지 않는다.

### There's more

`weak_ptr`은 **순환 참조**를 해결할 수 있다.

```cpp
struct Node {
    shared_ptr<Node> next;     // 자식은 강한 참조
    weak_ptr<Node>   parent;   // 부모는 약한 참조
};
```

`A → B`, `B → A`가 모두 `shared_ptr`이면 서로의 카운트를 1씩 붙들고 있어서 **둘 다 영원히 0이 되지 않는다.**
한쪽을 `weak_ptr`로 바꾸면 고리가 끊어져 정상적으로 해제된다.

## 관리 객체의 멤버 공유하기

`shared_ptr`는 동일한 자원에 대해 다른 독립적인 포인터로 공유할 수 있는 **별칭 생성자(aliasing constructor)** 를 제공한다.

### How to do it

```cpp
struct animal {
    string name{};
    string sound{};

    animal(const string& n, const string& a) : name{n}, sound{a} {
        cout << format("ctor: {}\n", name);
    }

    ~animal() {
        cout << format("dtor: {}\n", name);
    }
};

auto make_animal(const string& n, const string& s) {
    auto ap = make_shared<animal>(n, s);
    auto np = shared_ptr<string>(ap, &ap->name);
    auto sp = shared_ptr<string>(ap, &ap->sound);
    return tuple(np, sp);
}

int main() {
    auto [name, sound] = make_animal("Velociraptor", "Grrrr!");
    cout << format("The {} says {}\n", *name, *sound);
    cout << format("Use count: name {}, sound {}\n", name.use_count(), sound.use_count());
}
```

`make_animal`에서 이름과 소리만 공유하는 `shared_ptr`을 생성한다.

`shared_ptr<string>(ap, &ap->name)`이 별칭 생성자다.
**수명은 `ap`(animal 전체)를 따라가고, 가리키는 대상은 `name` 멤버**인 포인터가 만들어진다.
함수가 끝나면서 `ap` 자체는 사라지지만, `np`와 `sp`가 카운트를 붙들고 있으므로 animal 객체는 살아남는다.
그래서 소멸자 로그는 `main`이 끝날 때 찍힌다.

### How it works

공유 포인터는 **제어 블록**을 사용하여 자원을 관리한다.
하나의 제어 블록은 하나의 관리 객체와 연계되고, 그 객체를 공유하는 포인터들 사이에 공유된다.

별칭 공유 포인터의 경우 제어 블록은 **별칭 객체에 대한 포인터**를 포함한다.
즉 `shared_ptr`은 (제어 블록 포인터 + 실제 가리키는 대상 포인터) 두 개를 들고 다니며, 이 둘이 서로 다를 수 있다는 게 별칭 생성자의 정체다.

## 난수 엔진 비교하기

난수 라이브러리는 **엔진(생성기)** 과 **분포**로 역할이 나뉜다.
엔진은 균등한 비트열을 만들고, 분포는 그것을 원하는 범위·모양으로 바꾼다.

### How to do it

```cpp
std::random_device rd;                 // 비결정적 시드 소스
std::default_random_engine e{ rd() };  // 시드를 받아 난수 생성

std::mt19937 mt{ rd() };               // 메르센 트위스터
std::minstd_rand lc{ rd() };           // 선형 합동
```

각 엔진으로 히스토그램을 그려 비교해보면, **샘플 수를 늘릴수록 거의 같은 모양**이 나온다.
엔진마다 알고리즘은 다르지만 결국 모두 균등 분포를 목표로 하기 때문이다.

### How it works

엔진은 내부 상태를 갖고, 호출될 때마다 그 상태를 정해진 규칙으로 갱신하며 값을 뱉는다.
그래서 **같은 시드로 시작하면 항상 같은 수열**이 나온다.

엔진마다 다른 것은 결과의 "무작위스러움"보다는 이런 특성들이다.

| 엔진 | 특징 |
| --- | --- |
| `minstd_rand` | 선형 합동. 빠르고 상태가 작지만 주기가 짧다 |
| `mt19937` | 메르센 트위스터. 주기가 매우 길고 품질이 좋지만 상태가 크다(약 2.5KB) |
| `default_random_engine` | 구현체가 고른 기본 엔진. 무엇인지는 컴파일러마다 다르다 |

### There's more

라이브러리의 각 난수 생성 엔진은 서로 다른 방법론과 특성을 가지고 있는데, **매번 동일한 수열을 생성한다.**
이건 결함이 아니라 기능이다. 시드를 고정하면 테스트나 시뮬레이션을 **재현**할 수 있다.

하지만 `std::random_device`는 대부분의 시스템에서 **비결정적**이다.
하드웨어 엔트로피나 OS의 난수원을 사용하므로 실행할 때마다 다른 값이 나온다. 그래서 보통 **시드 공급용으로만** 쓰고, 대량 생성에는 엔진을 쓴다.

> 단, `random_device`가 진짜 비결정적인지는 **구현에 달려 있다.** 일부 구현에서는 고정된 값을 반환하기도 한다.
> 암호학적 보안이 필요하다면 표준 난수 라이브러리가 아니라 전용 암호 라이브러리를 써야 한다.

## 난수 분포 생성기 비교하기

### How to do it

분포를 비교하려면 **표본과 제수**가 필요하다.
값의 범위를 구간으로 나눠 각 구간에 몇 개가 들어오는지 세는 것이다.

```cpp
constexpr size_t n_samples{ 1000 };
constexpr size_t n_partitions{ 10 };

std::random_device rd;
std::mt19937 rng{ rd() };
std::uniform_int_distribution<int> dist{ 0, 99 };

std::array<size_t, n_partitions> hist{};
const size_t divisor = 100 / n_partitions;   // 제수 — 값을 구간 인덱스로

for (size_t i{}; i < n_samples; ++i) {
    ++hist[dist(rng) / divisor];
}
```

엔진은 그대로 두고 분포만 바꿔 끼우면 히스토그램 모양이 달라진다.

```cpp
std::uniform_int_distribution<int>  d1{ 0, 99 };   // 평평함
std::normal_distribution<double>    d2{ 50, 10 };  // 종 모양
std::bernoulli_distribution         d3{ 0.75 };    // true/false
```

### How it works

분포는 **엔진이 만든 균등한 난수를 원하는 확률 모양으로 변환하는 함수 객체**다.
`dist(rng)`처럼 엔진을 인자로 받아 호출한다.

여기서 역할 분리가 중요하다.

- **엔진** — 무작위성을 만든다. 바꾸면 품질과 속도가 달라진다.
- **분포** — 그 무작위성을 해석한다. 바꾸면 결과의 모양이 달라진다.

그래서 `rand() % 100` 같은 옛 방식과 달리, 범위 편향(modulo bias) 없이 정확한 분포를 얻을 수 있다.

### There's more

주요 분포는 용도별로 이렇게 나뉜다.

| 분류 | 분포 | 쓰임 |
| --- | --- | --- |
| 균등 | `uniform_int_distribution`, `uniform_real_distribution` | 주사위, 무작위 선택 |
| 베르누이 | `bernoulli_distribution`, `binomial_distribution` | 확률 p로 성공/실패 |
| 정규 | `normal_distribution`, `lognormal_distribution` | 키·오차처럼 평균 주변에 몰리는 값 |
| 푸아송 | `poisson_distribution`, `exponential_distribution` | 단위 시간당 발생 횟수, 대기 시간 |

분포 객체도 **내부 상태를 가질 수 있다.** 예를 들어 `normal_distribution`은 한 번에 두 개의 값을 계산해 하나를 저장해두기도 한다.
그래서 분포 객체는 매번 새로 만들지 말고 **재사용**하는 편이 좋다.
