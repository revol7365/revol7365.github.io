## 새로운 span 클래스를 사용하여 C 배열을 안전하게 만들기

연속적인 객체의 뷰를 생성하는 단순한 래퍼이며, 그 자체로 데이터를 가지지 않고 하위 데이터를 참조한다.
하위 자료 구조는 C 배열, 벡터, 혹은 STL array를 지원한다. C 배열을 넘기면 span으로 승격된다.

### How to do it

```cpp
template<typename T>
void pspan(span<T> s)
{
    cout << format("number of elements: {}\n", s.size());
    for (auto e : s) cout << format("{} ", e);
    cout << "\n";
}
```

span의 목적은 원시 데이터를 캡슐화하여 최소한의 오버헤드로 안전함과 편리함을 제공하는 것이다.

### How it works...

```cpp
template<typename T, size_t Extent = std::dynamic_extent>
class span {
    T* data;
    size_t count;
public:

};
```

- `Extent` 인자는 `constexpr size_t` 타입의 상수로 컴파일 타임에 계산된다.
- 하위 데이터 요소의 개수나 가변적인 크기를 나타내는 `std::dynamic_extent` 상수.
- 이를 통해서 벡터와 같은 자료 구조를 사용할 수 있다.

## 구조적 바인딩을 사용하여 다수의 값 반환하기

구조적 바인딩은 구조에 있는 값을 별도의 변수로 쉽게 언팩 해주어 코드의 가독성을 개선해 준다.

```cpp
pair<int, int> things_pair{ 47, 9 };
auto [this, that] = things_pair;
cout << format("{} {}\n", this, that);
// 47 9
```

### How to do it

구조적 바인딩은 pair, tuple, array, struct, C++20부터는 비트 필드도 포함된다.
구조적 바인딩은 자동 타입 추론을 사용하기 때문에 타입은 `auto`가 되어야 한다.

```cpp
// C 배열
int nums[]{ 1, 2, 3, 4, 5 };
auto [ a, b, c, d, e ] = nums;
cout << format("{} {} {} {} {}\n", a, b, c, d, e);
// 1 2 3 4 5

// STL array
array<int, 5> nums{ 1, 2, 3, 4, 5 };
auto [ a, b, c, d, e ] = nums;
cout << format("{} {} {} {} {}\n", a, b, c, d, e);
// 1 2 3 4 5

// tuple
tuple<int, double, string> nums{ 1, 2.7, "three" };
auto [ a, b, c ] = nums;
cout << format("{} {} {}\n", a, b, c);
// 1 2.7 three

// struct
struct Things { int i{}; double d{}; string s{}; };
Things nums{ 1, 2.7, "three" };
auto [ a, b, c ] = nums;
cout << format("{} {} {}\n", a, b, c);
// 1 2.7 three

// 참조
array<int, 5> nums{ 1, 2, 3, 4, 5 };
auto& [ a, b, c, d, e ] = nums;
cout << format("{} {}\n", nums[2], c);
c = 47;
cout << format("{} {}\n", nums[2], c);
// 3 3
// 47 47
```

배열에 const를 선언하면 변경을 막을 수 있다.

### How it works...

- 구조적 바인딩에서 타입을 `auto`로 하지 않으면 적절한 오류 메시지가 발생한다.
- 함수의 반환 타입에 사용하는 것이 일반적이다.
- map 컨테이너 클래스는 각 요소의 쌍을 반환하기 때문에, 구조적 바인딩을 사용하면 키/값 쌍을 편리하게 가져올 수 있다.

## if와 switch 문 안에서 변수 초기화하기

### How to do it

```cpp
const string artist{ "Jimi Hendrix" };
size_t pos{ artist.find("Jimi") };
if (pos != string::npos)
{
    cout << "found\n";
}
else
{
    cout << "not found\n";
}

// pos 변수가 조건문 밖으로 노출되어 관리가 필요하고,
// 동일한 심볼을 사용하면 충돌이 발생한다.
// 이때 초기화를 조건문 안으로 넣을 수 있다.
// 이렇게 되면 네임스페이스가 깨끗해지고 유지보수성이 높아진다.
if (size_t pos{ artist.find("Jimi") }; pos != string::npos)
{
    cout << "found\n";
}
else
{
    cout << "not found\n";
}
```

### How it works...

if문에서 사용된 초기화 표현식:

```cpp
if (auto var{ init_value }; condition)
{
    // var 변수 사용 가능
} else
{
    // var 변수 사용 가능
}
    // var 변수 사용 불가
```

switch문에서 사용된 초기화 표현식:

```cpp
switch (auto var{ init_value }; var)
{
case 1: // ...
case 2: // ...
case 3: // ...
default: // ...
}
    // var 변수 사용 불가
```

### There's more

사용 예시 중 하나는 뮤텍스를 잠그는 `lock_guard`의 범위를 제한하는 것이다.

```cpp
if (lock_guard<mutex> lg{ my_mutex }; condition)
{
    // 여기서만 사용된다
}

// 여기에서는 해제
```

생성자에서 잠그고 소멸자에서 해제를 하기 때문에 조건문 밖에서는 해제가 된다.

## 템플릿 인수 추론을 사용하여 단순성과 명확성 높이기

템플릿 인수 추론은 템플릿 함수나 클래스 템플릿 생성자의 인수 타입이 충분히 명확하여(기준이 뭐지??) 템플릿 인수를 사용하지 않고도 컴파일러가 이를 이해할 수 있을 때 발생한다.

### How to do it

```cpp
template<typename T>
const char* f(const T a)
{
    return typeid(T).name();
}

int main()
{
    cout << format("T is {}\n", f(47));
    cout << format("T is {}\n", f(47L));
    cout << format("T is {}\n", f(47.0));
    cout << format("T is {}\n", f("47"));
    cout << format("T is {}\n", f("47"s));
}
```

리터럴은 참조로 추론할 수 없다. (왜?)

```cpp
template<typename T>
const char* f(const T& a) {
    return typeid(T).name();
}

int main() {
    int x{ 47 };
    f(47); // 컴파일 오류 발생
    f(x);  // 추론 가능
}
```

C++17부터 클래스에 대한 템플릿 인수 추론(CTAD)이 가능하다.

```cpp
pair p(47, 47.0);    // pair<int, double>로 추론됨.
tuple t(9, 17, 2.5); // tuple<int, int, double>로 추론됨.
```

### How it works...

```cpp
template<typename T1, typename T2, typename T3>
class Thing {
    T1 v1{};
    T2 v2{};
    T3 v3{};

public:
    explicit Thing(T1 p1, T2 p2, T3 p3)
        : v1{ p1 }, v2{ p2 }, v3{ p3 } {
    }

    string print() {
        return std::format("{}, {}, {}\n",
            typeid(v1).name(),
            typeid(v2).name(),
            typeid(v3).name()
        );
    }
};

// 이걸
Thing<int, double, string> thing1{ 1, 47.0, "three" };
// 이렇게 할 수 있다. 더 단순하고 오류 발생 가능성이 적다.
Thing thing1{ 1, 47.0, "three" };
```

### There's more

파라미터 팩이 포함된 생성자의 사례:

```cpp
template<typename T>
class Sum {
    T v{};
public:
    template<typename... Ts>
    Sum(Ts&&... values) : v{ (values + ...) } {}
    const T& value() const { return v; }
};
```

폴드 표현식: `values + ...`
C++17 기능으로 파라미터 팩의 모든 멤버에 이 연산자를 사용한다. 이 경우 파라미터 팩의 모든 값을 합하여 `v` 변수를 초기화한다.

```cpp
Sum s1{ 1u, 2.0, 3.4f }; // unsigned, double, float
Sum s2{ "abc"s, "def" };  // std::string
```

이것은 컴파일되지 않는다. 템플릿 인수 추론이 서로 다른 매개변수에 대해 공통 타입을 찾는 데 실패한다.
이를 해결하려면 템플릿 추론 가이드가 있어야 한다. 컴파일러에게 `std::common_type_t`라는 특성을 사용하도록 지시한다.

## if constexpr 문을 사용하여 컴파일 타임 결정 단순화하기

`if constexpr` 조건문은 컴파일 타임 조건에 따라 코드가 실행될 필요가 있을 때 사용된다.

### How to do it

```cpp
template<typename T>
auto value_of(const T v)
{
    if constexpr (std::is_pointer_v<T>)
    {
        return *v; // 포인터를 역참조
    } else
    {
        return v; // 값을 반환
    }
}

int main()
{
    int x{ 47 };
    int* y{ &x };
    cout << format("value is {}\n", value_of(x)); // 값
    cout << format("value is {}\n", value_of(y)); // 포인터
    return 0;
}

// value is 47
// value is 47
```

`if constexpr` 문을 사용하면 코드에서 포인터와 값을 쉽게 구별할 수 있다.

### How it works...

`if constexpr` 문은 정상적인 if문처럼 동작하지만 컴파일 타임에 평가된다는 차이가 있다.
런타임 코드에는 `if constexpr` 문에서 발생하는 분기문이 포함되지 않는다.

```cpp
if constexpr (std::is_pointer_v<T>) {
    return *v; // 포인터를 역참조
}
else {
    return v; // 값을 반환
}
```

조건 `is_pointer_v<T>`는 런타임에서 사용 불가한 템플릿 인자를 검사한다.
`constexpr` 키워드는 템플릿 인자 `<T>`가 사용 가능하다면, 컴파일러에 if문이 컴파일 타임에 평가되어야 함을 알린다.
